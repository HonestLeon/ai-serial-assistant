## 1. 整体链路与协议概览

```
┌────────────────────────┐     USB/串口      ┌────────────────────────┐
│  上位机（PC 端）         │ ◄──────────────► │  开发板（嵌入式端）      │
│  AI 串口调试助手          │   115200 默认     │  被控对象 + PID 控制    │
│  · 下发指令（下行）        │ ───────────────► │  · 解析 SET_POINT 等指令 │
│  · 采集响应（上行）        │ ◄─────────────── │  · 周期上报 target/...   │
└────────────────────────┘                  └────────────────────────┘
```

**调参闭环**（真实串口模式）：
1. 智能体（上位机）下发 `SET_POINT <值>` 修改目标值（制造阶跃）
2. 开发板收到指令后更新目标变量，PID 控制开始跟随
3. 开发板**周期**把 `目标值,反馈值,控制量` 以文本行回传
4. 上位机把数据写入数据缓冲 → 本地算响应指标 → 决策下一组参数 → 再下发阶跃……
5. 越限时上位机自动回退并告警

**要点**：上位机只自动下发「目标值」指令（`SET_POINT`）；PID/前馈参数指令集（`PID`/`SET`）在嵌入式端**已就绪但上位机当前版本尚未自动下发**（见路线图进行中项），建议嵌入式端一并实现，供手动测试与未来版本使用。

## 2. 上行数据：板 → 上位机（周期上报）

上位机在「真实串口」模式下，对收到的每一行文本做如下解析（`usePidAgent.onSerialData`）：

- 取 `:` 冒号**之后**的片段（无冒号则用整行）
- 用正则 `[-+]?\d*\.?\d+` 提取数值
- **每行必须 ≥ 3 个数值**，按顺序取前三个作为：`[目标值, 反馈值, 控制量/输出]`
- 不足 3 个数值的行会被**直接丢弃**

因此嵌入式端需要满足：

| 要求 | 说明 |
|------|------|
| **文本行、以 `\n` 结尾** | 上位机 Raw 引擎按 `\n` 分行；容忍 `\r\n` |
| **每行 ≥ 3 个数值** | `目标值 反馈值 控制量`，逗号/空格分隔均可 |
| **第 1 个数 = 当前目标值** | 上位机靠它识别「阶跃」起点，必须是 `read_target()` 返回的实时目标 |
| **普通十进制小数** | 正则不支持科学计数法（`1e-3` 会被拆成 `1` 和 `-3`），请用 `%.4f` 这类格式 |
| **固定周期发送** | 建议 1ms / 5ms / 10ms，响应曲线分辨率与安全检测质量挂钩 |

**合法行示例**：

```
100.0000,50.0000,30.0000
CTRL: 100 50 30 50
target,feedback,output: 100.0000,50.0000,30.0000
```

> ⚠ **常见坑**：项目自带模板 `zhichuan_periodic_send()` 目前只发 **2 个值**（`target,feedback`），会被上位机丢弃。使用时必须在模板基础上追加第 3 个值（控制量/输出）。见[第 4 节](#4-推荐的集成方式复用-zhichuan-通信层模板)与[第 8 节示例](#8-附完整示例代码基于-stm32-hal)。

## 3. 下行指令：上位机 → 板

嵌入式端需实现一个**文本行指令解析器**（`\n` 结尾、不区分大小写、容忍 `\r\n`）：

| 指令 | 含义 | 当前上位机是否自动下发 |
|------|------|------------------------|
| `SET_POINT <value>` | 修改目标值（阶跃） | ✅ 是（`set_target` 工具） |
| `PID <kp> <ki> <kd>` | 单环批量设主参数 | ⏳ 指令集已就绪，尚未自动下发 |
| `PID <spKp> <spKi> <spKd> <poKp> <poKi> <poKd>` | 串级批量设 6 参数（速度环在前、位置环在后） | ⏳ 同上 |
| `SET <type> <value>` | 单参数修改（type 见宏，含 PID 与前馈系数） | ⏳ 同上 |

**参数 type 宏**（来自 `zhichuan_pid.h`）：

| type | 含义 | | type | 含义 |
|------|------|-|------|------|
| `0x01` | 单环 Kp | | `0x07` | 串级 位置环 Kp |
| `0x02` | 单环 Ki | | `0x08` | 串级 位置环 Ki |
| `0x03` | 单环 Kd | | `0x09` | 串级 位置环 Kd |
| `0x04` | 串级 速度环 Kp | | `0x10`~`0x1A` | 前馈项系数（线性/二次/…/目标二阶导） |
| `0x05` | 串级 速度环 Ki | | | |
| `0x06` | 串级 速度环 Kd | | | |

> 前馈启用位掩码：`ZHICHUAN_FF_*`（bit0~bit10），由上位机根据你勾选的前馈项生成总掩码 `ZHICHUAN_FF_MASK`，写入模板头文件。你的工程据此判断运行时计算哪些前馈项（见模板 `.h` 内注释示例）。

## 4. 推荐的集成方式：复用 zhichuan 通信层模板

模板只做**通信层**，不含 PID/前馈计算——你的控制算法原样保留，只需把模板接入，让上位机的参数/目标变更落到你工程的真实变量上。

### 4.1 加入工程

把 `zhichuan_pid.c` 与 `zhichuan_pid.h` 复制到你的工程，加入编译。

### 4.2 实现函数指针（注入到 `ZhichuanTuningConfig`）

| 函数指针 | 必填 | 你的实现 |
|----------|------|----------|
| `read_feedback()` | ✅ | 返回被控量实测值（编码器/ADC 折算后的物理量） |
| `read_target()` | ✅ | 返回当前目标变量（**SET_POINT 更新后必须读到新值**） |
| `set_param(type, value)` | ✅ | 按 type 把 value 写到你工程实际的 PID/前馈变量上，并立即生效 |
| `set_target(value)` | ✅ | 更新目标变量（可带斜坡/限幅） |
| `serial_write(data, len)` | ✅ | 你的串口发送函数（非阻塞或短阻塞均可） |
| `serial_read()` | 可选 | 轮询式读单字节（返回 -1 表示无数据）；用中断方式可填 NULL |

### 4.3 挂载调用

```c
ZhichuanTuningConfig g_tuning = {
    .read_feedback = my_read_feedback,
    .read_target   = my_read_target,
    .set_param     = my_set_param,
    .set_target    = my_set_target,
    .serial_write  = my_uart_write,
    .serial_read   = NULL,   /* 中断方式用 NULL */
};

/* ① 控制循环：固定周期（如 5ms）调用，上报 target/feedback/output */
void ControlLoop_Task(void) {
    RunMyPid();                     /* 你原有的控制逻辑 */
    zhichuan_periodic_send(&g_tuning);
}

/* ② 串口接收中断：逐字节喂给指令解析器 */
void UART_RxCpltCallback(UART_HandleTypeDef *huart) {
    if (huart == &huart1) {
        uint8_t b = g_rx_byte;
        zhichuan_parse_command(&g_tuning, b);
        HAL_UART_Receive_IT(&huart1, &g_rx_byte, 1);
    }
}
```

### 4.4 改造周期发送函数（关键！）

模板原版只发 2 个数会被上位机丢弃，请改成 **3 个数（target, feedback, output）**：

```c
void zhichuan_periodic_send(const ZhichuanTuningConfig *cfg) {
    if (!cfg || !cfg->read_feedback || !cfg->read_target || !cfg->serial_write) return;
    float target   = cfg->read_target();    /* 目标值（第 1 个） */
    float feedback = cfg->read_feedback();  /* 反馈值（第 2 个） */
    float output   = my_read_output();      /* 控制量/输出（第 3 个，自己补） */
    char line[64];
    int n = snprintf(line, sizeof(line), "%.4f,%.4f,%.4f\n",
                     (double)target, (double)feedback, (double)output);
    if (n > 0) cfg->serial_write((const uint8_t *)line, (uint16_t)n);
}
```

> 若你的控制量不方便读，也可用**误差**或任意第 3 个数顶位（上位机只取前 3 个数做 `[target, feedback, output]`），只要数值合理即可。

## 5. 上位机侧操作步骤

1. 左侧「协议与连接」：数据引擎选 **Raw（文本行）**，配置波特率（与板子一致，默认 115200），点「打开串口」。
2. 切到「PID 调参」标签页，把「测试来源」切到 **真实串口**（需先连接设备才能启动智能体）。
3. 左栏配置（务必与设备实际量程一致）：
   - ① **PID 参数**：初始值与取值范围（护栏第一重约束）
   - ② **信号安全范围**：控制值 / 反馈值 / 目标值的 min ~ max——**与设备物理量程对齐**，否则目标值会被裁剪或拒绝
   - ③ **前馈项**：按需添加
   - ④ **控制场景提示词**：描述被控对象与约束（如「直流电机速度环，额定转速 3000rpm，带 5:1 减速器，允许 10% 超调」）
4. 右侧输入任务描述 →「开始调参」。智能体会自动下发 `SET_POINT` 阶跃、读取你的响应曲线、计算指标、再决策。

## 6. 联调流程与注意事项

### 6.1 建议的联调顺序

1. **先验证上行**：打开串口后，确认「数据流」能持续看到 `target,feedback,output` 文本行。
2. **再验证下行**：在「数据流」发送框手动发 `SET_POINT 100`，确认板上目标变量被修改、返回行的第 1 个数变为 100。
3. **最后跑智能体**：确认响应曲线正常后，再启动「PID 调参 · 真实串口」。

### 6.2 注意事项

| 事项 | 说明 |
|------|------|
| **目标值必须是第 1 个数** | 否则上位机检测不到阶跃，分析会显示「无阶跃 / 数据不足」 |
| **采样周期稳定** | 周期抖动大会让上升/稳定时间计算失真；建议 ≤ 10ms |
| **安全检测窗口约 5 秒** | `set_target` 下发后，上位机收集约 5 秒响应做安全判定；系统稳定时间过长时指标会受影响（`get_channel_stats` 仍可查更长区间） |
| **设备端物理安全** | 上位机护栏是软件层，**不能替代硬件保护**：输出限幅、电流/位置限位、急停必须留在板子本地 |
| **目标阶跃别太猛** | 智能体可能在安全范围内多次改目标，注意机械冲击与温升 |
| **set_param 要立即生效** | 修改 PID 变量后控制循环要实时读到新值，不要只在下次上电生效 |
| **行缓冲长度** | 模板行缓冲 64 字节，请勿发超长行（会被丢弃） |
| **不区分大小写** | 指令解析不区分大小写，发送端大小写随意 |

## 7. 常见问题排查

| 现象 | 排查方向 |
|------|----------|
| 智能体提示「串口模式下请先连接设备」 | 未打开串口 / 串口被占用；先到左侧打开串口 |
| 「数据流」看不到数据 | 波特率不一致、接线错误、引擎选错、行未以 `\n` 结尾 |
| 能看到数据但智能体不采集 | 每行**不足 3 个数值**会被丢弃——确认发的是 `target,feedback,output` 三值 |
| 发送 `SET_POINT` 后第 1 个数没变 | `set_target` 没有更新 `read_target()` 返回的变量；或指令没被解析（检查是否 `\n` 结尾、字节流是否进中断） |
| 分析提示「样本不足 / 无阶跃」 | 数据没进来或目标值没变；先按 6.1 手动验证上下行 |
| 目标值被裁剪/拒绝 | 「信号安全范围」与设备量程不匹配，回左栏核对 |

## 8. 附：完整示例代码（基于 STM32 HAL）

> 下面是一个可直接参考的完整接入示例：单环电机速度环 + USART1（115200，中断接收）。核心控制算法（PID 计算）留空，由你自己的工程实现。

```c
/* ---- my_tuning_glue.c ---- */
#include "zhichuan_pid.h"
#include "main.h"

/* ---- 用户控制变量（你的工程实际使用的变量） ---- */
extern volatile float g_target;    /* 目标转速/位置 */
extern volatile float g_feedback;  /* 实测反馈 */
extern volatile float g_output;    /* 控制量（PWM 占空比等） */
extern float g_kp, g_ki, g_kd;     /* 单环 PID 参数，控制循环实时读取 */

/* ---- ① 数据读取（函数指针实现） ---- */
static float my_read_target(void)   { return g_target; }
static float my_read_feedback(void) { return g_feedback; }
static float my_read_output(void)   { return g_output; }

/* ---- ② 串口写（HAL 非阻塞或阻塞均可） ---- */
static void my_uart_write(const uint8_t *data, uint16_t len) {
    HAL_UART_Transmit(&huart1, (uint8_t *)data, len, 10);
}

/* ---- ③ 参数写入：把上位机指令落到真实变量（单环示例；串级/前馈按宏扩展） ---- */
static void my_set_param(uint8_t type, float value) {
    switch (type) {
        case ZHICHUAN_PARAM_KP: g_kp = value; break;
        case ZHICHUAN_PARAM_KI: g_ki = value; break;
        case ZHICHUAN_PARAM_KD: g_kd = value; break;
        /* 串级：ZHICHUAN_PARAM_SPEED_KP/KI/KD、ZHICHUAN_PARAM_POSITION_KP/KI/KD */
        /* 前馈：ZHICHUAN_PARAM_FF_*（0x10~0x1A），写入对应系数变量 */
        default: break;
    }
}

/* ---- ④ 目标写入（可带斜坡/限幅） ---- */
static void my_set_target(float value) {
    g_target = value;   /* 建议按你的量程做限幅 */
}

/* ---- ⑤ 配置结构体 + 中断字节缓存 ---- */
static ZhichuanTuningConfig g_tuning = {
    .read_feedback = my_read_feedback,
    .read_target   = my_read_target,
    .set_param     = my_set_param,
    .set_target    = my_set_target,
    .serial_write  = my_uart_write,
    .serial_read   = NULL,   /* 中断接收，无需轮询 */
};
volatile uint8_t g_rx_byte = 0;

/* ---- ⑥ 控制循环（示例：5ms 周期任务） ---- */
void ControlLoop_5ms(void) {
    MyPidCompute();                 /* 你原有的 PID 计算，读 g_target/g_feedback，写 g_output */
    zhichuan_periodic_send(&g_tuning);   /* 周期上报 target,feedback,output */
}

/* ---- ⑦ USART1 接收中断：逐字节喂给指令解析器 ---- */
void HAL_UART_RxCpltCallback(UART_HandleTypeDef *huart) {
    if (huart->Instance == USART1) {
        zhichuan_parse_command(&g_tuning, g_rx_byte);
        HAL_UART_Receive_IT(&huart1, (uint8_t *)&g_rx_byte, 1);
    }
}

/* main() 初始化处：开启中断接收 */
/* HAL_UART_Receive_IT(&huart1, (uint8_t *)&g_rx_byte, 1); */
```

**移植到其他平台**：把 `my_uart_write` / `my_uart_read` / 中断回调换成对应平台的串口 API 即可，通信层与平台无关。

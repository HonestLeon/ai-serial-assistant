# AI 串口调试助手 · 高级目标功能规格说明

> 版本：V1（目标态，非当前实现）
> 日期：2026-07-20（范围说明于 2026-07-26 更新）
> 范围：本文档描述产品"目标应具备"的功能，作为开发路线图与对外沟通的基线。当前 demo 已实现：串口收发（Raw/JustFloat）、实时波形、本地确定性响应分析、AI 结构化解释（离线降级）、PID 辅助调参（策略注册表 + 安全护栏 + 人工确认）、仿真模式自动调参闭环、嵌入式 `.c/.h` 通信层导出。尚未实现：系统辨识+ZN 初值、离线信号处理降级、策略模板扩充、自动调参向真实硬件延伸。

## 1. 总体架构

两大支柱模块，共用底层。**实现顺序上，波形分析是前置基础**——先打通"数据采集 → 特征提取 → 对比可视化"的数据回路；自动调参建立在这条回路之上叠加（且自动调参实现难度更高，故放在后阶段）。

- **波形分析模块**：面向串口时序数据的特征提取、对比与智能解读（前置基础，先打通数据回路）。
- **调参模块（⭐核心）**：面向竞赛控制系统的辅助式参数整定，建立在波形分析打通的数据回路上。

共用底层：串口协议解析层（Raw / JustFloat / FireWater 等）、数据缓冲、回放与绘图层、AI 引擎（离线 + 云端双模）。

```
┌─────────────────────────────────────────────┐
│             AI 串口调试助手                    │
├──────────────────────┬──────────────────────┤
│   波形分析模块        │   调参模块（⭐核心）   │
│  · 数据特征/自动EDA  │   · 策略分层          │
│  · 双数据对比        │   · 输出函数 F=...    │
│  · 数据打包给AI      │   · 安全限制/回退     │
│  · 波形分析报告      │   · .c/.h 导出        │
│                      │   · 日志/报告         │
├──────────────────────┴──────────────────────┤
│ 底层：协议解析·数据缓冲/回放/绘图·AI引擎(离线+云)│
└─────────────────────────────────────────────┘
```

## 2. 波形分析模块（前置基础）

### 2.1 数据特征与自动 EDA

- 对选定通道自动计算统计特征：峰值、均值、方差、斜率、稳态值、极值等。
- 自动生成 EDA 图（时序图、分布直方图、箱线图等），无需用户写脚本。

### 2.2 双数据对比（目标值 vs 实际值）

- 支持**手动选择两组数据**进行叠加对比（如设定值 / 目标值 与 实际输出）。
- 自动计算控制指标：**响应速度（上升时间 / 调节时间）、超调量、稳态误差、RMSE**，用量化指标替代"肉眼看波形"。
- **指标计算用确定性代码实现**（而非调用 LLM）：保证结果可复现、零延迟、无网络依赖。

### 2.3 数据如何打包给 AI

打包策略（结构化上下文，降低 token 消耗、提升专业度）：

1. **元数据**：系统类型、控制结构、采样率、通道映射；
2. **当前参数与输出函数**（仅自动调参模式）；
3. **关键统计特征**（而非原始万级采样点）+ 必要时下采样的曲线摘要；
4. **用户选定的异常现象标签**（超调 / 震荡 / 稳态误差）。
5. **原始数据预处理**：变化不大的区段可做压缩 / 下采样，进一步降低 token 与传输开销。

- 离线时仅用 1–3 项做特征统计；联网时附第 4 项交给 LLM 做诊断。

### 2.4 波形分析报告

- 综合 2.1–2.3，生成可读的**波形分析报告**：现象描述 + 量化指标 + 可能原因 + 建议调整方向。

## 3. 调参模块（⭐核心功能）

### 3.1 策略分层：不同系统 / 不同控制 → 不同调参策略

引入"**策略注册表**"：每个被支持的系统 / 控制结构对应一条策略，定义"要调哪些参数、什么顺序、什么指标算达标"。

按控制结构分多档，这里先举两档：

| 控制结构 | 典型系统 | 待整定参数 |
|---|---|---|
| 线性系统（近似） | 空载电机、yaw 轴云台 | {Kp, Ki, Kd} |
| 非线性系统 | pitch 云台、平衡车直立环 | PID 三项 + 前馈额外参数（如模型增益 Kff、重力补偿项等） |

> 设计要点："不同系统不同策略、不同控制不同调参策略"通过同一注册表表达，新增系统只需新增一条策略配置，无需改主流程。

### 3.2 输出函数机制 `F = f_pid(error) + f_ff(target)`

- 用户可**提前定义控制器输出函数**，显式写出两项：
  - `f_pid(error)`：误差驱动的 PID 项，一般 $$ f_pid(error) = Kp \cdot error + Ki \cdot \int error \, dt + Kd \cdot \dot error \ $$.
  - `f_ff(target)`：基于目标 / 设定的前馈项（利用物理模型预补偿）。
- 默认开启 PID，用户可根据需要选择前馈项（如模型增益 Kff、重力补偿项等，在对应选项后勾选）。
- **参数初始值**：用户可设置每个参数的初始值，用于引导 AI 调参；默认值为 0。
- **调参顺序由用户决定**：例如先调 Kp → 再调 Kd → 最后调前馈增益；顺序可拖拽 / 编排。
- **依次整定 + 用户审核**：按既定顺序逐个参数整定，每一步给出"建议值 + 依据"，**必须用户确认（审核）后才下发**——契合已验证的"辅助式调参"定位（调研中 71.4% 用户选择"给建议、手动确认"）。

### 3.3 参数安全限制与自动回退（防机械损伤）

- 每个参数设有**物理安全边界**（上 / 下限、变化率限制），由用户填写；**目标值同样需设限制**（用户填写），防止设定本身越界。
- 在线监控阶跃响应指标：**超调量、震荡（持续振荡 / 发散）** 一旦越界，触发**参数立即回退到上一稳定态**，防止烧毁电机 / 打坏机械结构。
- **安全逻辑优先级高于 AI**：检测到越界必须先在本地立即回退，并向云端模型反馈该异常；**而非先等待云端大模型决策再回退**——确保机械安全不被网络延迟拖累。
- 回退动作本身记录进日志，供复盘。
- 直接回应调研中用户的核心顾虑："怕乱调导致机械损坏"。

### 3.4 嵌入式集成：生成 `.c` / `.h`

自动调参的前提是：串口调试助手发出的"参数变更指令"与"目标值变化指令"能真正改变嵌入式芯片中的对应变量，并能回读目标值与反馈值。为此，生成的源码建议采用**函数指针注入**式集成：

在 `.c` 中实现：
1. **指令解析**：解析上位机下发的参数 / 目标值变更指令；
2. **修改参数 / 目标值**：执行实际写入；
3. **数据回传**：向上位机发送目标值与反馈值。

在 `.h` 中用**函数指针**指向用户工程已有的：
- 参数变更函数、目标值变更函数；
- 目标值获取函数、反馈值获取函数。

这样用户只需把 `.c/.h` 加入原工程并配置好这几个函数指针，即可启用自动调参，无需改动既有控制逻辑。

### 3.5 AI 引擎：离线 + 云端 LLM 双模

- **云端 LLM**：联网时提供"现象→参数"诊断、调参建议、报告润色。
- **离线模式**：无网 / 赛场环境下，降级为**信号处理 + 本地模型**（Ziegler-Nichols / 继电自整定 / Cohen-Coon 等），并给出数据特征统计（均值 / 峰值 / 方差）。
- 两种模式对用户透明切换。

### 3.6 日志与调参报告

- 每次调参会话自动留存：时间、系统类型、参数演进轨迹、每步指标、用户决策。
- 一键生成**调参报告**（含 before / after 阶跃响应对比图），可直接贴进竞赛设计报告 / 技术文档，把"省时间"落到文档产出上。

### 3.7 补充

- 可以考虑引入系统辨识功能。
- 可以考虑除了串口以外的其他通信方式，如连接 J-Link 调试器（参考 Ozone）。

## 4. MVP 与路线图（优先级）

实现顺序遵循"先波形分析、后自动调参"的依赖关系：先打通数据回路（采集 → 特征 → 对比可视化），再在其上叠加自动调参。

- **第一阶段 · 波形分析与数据回路（先落地）**：
  - 波形特征提取 / 双数据对比（响应速度、超调量，代码实现）；
  - 离线特征统计；
  - 数据打包给 AI + 波形分析报告。
- **第二阶段 · 自动调参**：
  - 线性系统 PID 调参；
  - 自主加入前馈项（如模型增益 Kff、重力补偿项等）；
  - 参数安全限制 / 自动回退；
  - 调参报告导出；
  - 给出 `.c` / `.h`（函数指针注入式集成）。
- **后续（V1.1+）**：
  - 非线性系统 PID 调参（pitch 云台、平衡车）；
  - 输出函数解析与自定义调参顺序；
  - 云端 LLM 诊断；
  - 参考开源策略库扩充。

> 说明：用户明确"MVP 先搞线性系统控制"，故高级能力列为后续阶段，避免 MVP 过度膨胀。

## 5. 与已确认产品定位的对应

| 功能点 | 对应的已验证定位 |
|---|---|
| 波形双数据对比（响应速度 / 超调量） | "专业性"——懂控制指标，而非只看波形（指标由代码算，确定可复现） |
| 数据打包给 AI（结构化上下文） | "结构化上下文"——喂给 AI 的是可解析的特征而非原始堆数据 |
| 调参过程需用户审核 | "辅助式调参"（调研 71.4% 要"给建议、手动确认"，而非全自动） |
| 参数安全限制 / 回退 | 回应"怕乱调损坏机械"的真实顾虑，建立信任 |
| 离线 + 云端 LLM | 满足赛场无网刚需（调研 57.1% 认为离线重要） |
| 不同系统 / 控制策略分层 | "场景化调参预设"，把抽象功能变具体交付物 |
| 生成日志 / 调参报告 | 贴合"时间紧"卖点，报告可直接进竞赛文档 |

## 6. 待澄清 / 风险（供后续讨论）

- **【已决议】输出函数形式**：采用**预设模板**而非完全自由函数——PID 为标准形式（暂只考虑标准 PID）；前馈为 target 的一元函数，类型限定为多项式、符号函数、三角函数等有限选项。符号解析复杂度因此可控。
- **【已决议】自动回退阈值**：默认超调 20%、震荡判定为连续振荡幅度 >10%，均可在"高级设置"中由用户调整，避免误触发打断正常整定。

# 前端问题排查与修复计划

> 排查对象：`ai-serial-assistant-app`（Electron 42 + Vue 3.5 + Element Plus 2.14 + ECharts 6）
> 排查范围：`src/renderer`（全部组件、composable、service）、`src/preload`、`src/main` 中与前端交互相关的部分
> 版本：**v1.1（2026-11-02 复核修订）** — 根据第二轮代码复核修正 6 处事实/方案错误，补充 4 项遗漏缺陷
> 结论：性能优化方向正确（IPC 合批、100ms 批刷新、稳定 key、ECharts 按需注册），但有 5 处**数据通路 / 生命周期 / 窗口可用性**缺陷会吃掉这些收益；另有 8 处健壮性问题和一批调试残留。

## 1. P0 详情

### FE-01 同 tick 覆盖导致采样丢失

**现象**
DataMonitor 每 100ms 把积压 payload 逐条 `emit('data', payload)`，App 的 `onData` 每次都执行 `latestPayload.value = payload`。子组件用 `watch(() => props.latestPayload)` 消费，而 Vue watcher 默认 `flush:'pre'`，同一 tick 内多次赋值会被调度器去重，**只有最后一次生效**。

**证据**
- `renderer/src/App.vue:188` — `latestPayload.value = payload`
- `renderer/src/components/DataMonitor.vue:276` — 在 flush 循环中逐条 emit
- `renderer/src/components/WorkspaceChart.vue:350`、`PidAgentPanel.vue:42` — 均为 `watch(latestPayload)`

**影响**
- 200 行/秒的设备，波形实际只有 10 点/秒；
- X 轴用的是样本序号（`sampleIndex++`）而非时间戳，丢点后时间比例也错；
- 智能体数据缓冲同样稀疏。

**修复方案（v1.1 修正：只保留"批事件"一种，不再使用共享 drain 队列）**
1. DataMonitor 改为 `emit('data-batch', batch)`，一次性上抛本批全部帧；
2. App 的 `onData` → `onDataBatch(batch)`：遍历 batch 完成 `rxCount` / `pushSerialContext` / `recording`；
3. 再把 batch 分发给两个消费者：图表经 ref 调用 `appendBatch(batch)`，智能体调用 `pushSerialBatch(batch)`。
4. 若坚持用共享队列，必须为每个消费者维护独立游标（`lastSeenIndex`），禁止两个消费者对同一数组 drain——否则先 drain 的吃光、后者拿到空数组，等于把"末条覆盖"换成"随机丢帧"。

**验收**
- 用「控制响应模拟」（50ms/帧）采集 10 秒：波形点数 ≈ 表格行数 ≈ 200，而不是 ≈100；
- **行为回归检查**：采样密度从 ~10Hz 提升到全速后，`tests/pid-agent-*.mjs` 与既有整定结论的指标会变化。需跑一遍仿真整定，将超调/稳态误差与旧结果对比，确认变化在合理范围内再合入。

### FE-02 隐藏的下半区仍在计算与渲染

**现象**
`App.vue:295`、`:319` 用 `v-show` 切换下半区的「数据 / PID 调参」，组件不卸载，依赖变更仍触发 render effect。

**证据**
- `App.vue:295` 的 `.data-split` 同时包含 DataMonitor 与 WorkspaceAnalysis；
- `DataMonitor.vue:278-280` 隐藏时照样 unshift 并 patch；
- `WorkspaceAnalysis.vue:38,90` 隐藏时照样重算统计。

**v1.1 更正**
上一版把 `WorkspaceChart` 也列入本条并建议"隐藏时停止重绘"——**这是错的**。波形区在 `App.vue` 上半区，始终可见，`App.vue:225` 的产品文案就是"实时波形持续可见"；停掉重绘恰好会毁掉调参时最需要看的波形。`WorkspaceChart.vue:28` 的 `visible` 是恒定 true 的遗留参数，应删除或另作他用。

**修复方案**
1. 只对 **DataMonitor + WorkspaceAnalysis** 做 `active` 门控（由 `activeTab === 'data'` 派生）；
2. DataMonitor 非激活时只入队不建表格行、不 patch（或把上限降到 500）；
3. WorkspaceAnalysis 非激活时把统计节流到 1Hz；
4. 波形区不动。

**验收**
切到 PID 页后 renderer 空闲时间上升；PID 页输入无可感知延迟；波形仍连续刷新。

**证据**：`SerialPanel.vue:43-49` 的 `localProtocol` 是影子状态，`onProtocolChange()` 只 `emit('update-protocol')` 不带值；`App.vue:51-54` 的 `saveProtocol()` 写的是从未被更新的 `protocolEngine.value`。

**验收**：选 FireWater → 重启 → 仍为 FireWater。

### FE-05 IPC 监听无取消接口

**证据**：`preload/index.js:15-17` 只 `ipcRenderer.on`，不返回取消函数；渲染层 0 处 `removeListener`（grep 确认）；`DataMonitor.vue:386`、`SerialPanel.vue:117/122` 注册后不清理。

**影响**：dev HMR 后消息重复处理；闭包无法回收。

**修复方案**：每个 `onXxx` 返回 `() => ipcRenderer.removeListener(channel, handler)`，组件 `onUnmounted` 调用。可抽 `useIpcSubscription`。

**验收**：HMR 后消息不重复；反复 mount/unmount 后 `listenerCount` 不增长。

### FE-06 录制 / 回放无上限与回放功能缺口

**证据**
- `App.vue:200` — `recording.data.push` 无封顶；
- `DataMonitor.vue:353-372` — 每帧一个 `setTimeout`；**回放期间 messages 不受 `MAX_MESSAGES` 约束**（只截断 `tableRows`），逐帧 O(n) unshift；
- 回放路径**不 `emit('data')`** → 波形、PID 智能体、rxCount 全部收不到回放数据；
- 回放路径**不调用 `scrollToTop()`** → 用户看不到内容在动。

**v1.1 更正**：上一版说"结束后闭包仍被数组持有"不准确——`setTimeout` 触发后回调即释放，`replayTimers` 留的是数字 id。真正的代价是 **N 个定时器一次性排程 + 后台节流导致绝对延迟漂移**，以及停止/自然结束后数组不清。

**影响**：200 帧/秒录 1 小时 ≈ 72 万对象；回放 10 万帧即 10 万个定时器，主线程抖动；回放时波形静止。

**修复方案**
1. 录制封顶（建议 20 万帧），到顶自动停止并提示；
2. 回放改单一调度器：按 `recTime` 差值 `await sleep(delta)` 逐帧播放，`AbortController` 停止；
3. 回放同样走 `emit('data-batch')`（复用 FE-01 的通道），并调用 `scrollToTop()`；
4. 回放消息套用与实时相同的 `MAX_MESSAGES` 截断；
5. 结束/停止时清空 `replayTimers`。

**验收**：30 分钟录制内存平稳；5 万帧回放无长任务；回放时波形与表格同步滚动；若决定回放不进入智能体，需在 UI 明确标注。

### FE-07 JustFloat 缓冲无限增长

**证据**：`main/serial.js:139-158`，`Buffer.concat` 无上限；`parseJustFloat` 找不到帧尾返回 `consumed:0` 并 break。

**修复方案**：设 64KB 上限，超限清空并 `serial:error` 提示协议不匹配；`concat` 改为 chunk 数组批量合并（当前是 O(n²) 拷贝）。

**验收**：JustFloat 模式下用文本协议持续发 1 分钟，主进程内存不增长且有提示。

### FE-08 串口异常 / 退出时的生命周期

**证据**
- `main/serial.js:172-174` — 只有 `on('error')` 发消息，不清理、不广播 status；
- **缺少 `port.on('close')`** — Windows 拔盘通常先/只触发 close；
- `main/index.js:72-76` — `window-all-closed` 直接 `app.quit()`，没有 before-quit 里 `closePort()`。

**影响**：拔线后仍显示"已连接"；异常路径下端口对象已死，直接调 `closePort()` 可能重入或对已销毁端口操作；退出后 COM 口可能短暂被占。

**修复方案**
1. 同时监听 error 与 close，统一走一个幂等的 `handlePortLost()`：只清理一次、广播 `serial:status({connected:false})`；
2. `closePort()` 增加重入保护（closing 标志 + 校验 currentPort === port）；
3. `app.on('before-quit')` 中先关串口再退出。

**验收**：拔线 1 秒内 UI 变未连接；异常后再点"打开串口"可正常重连；退出进程后立即重开可占用同一 COM 口。

### FE-16 Windows 上缺少可用的窗口控制按钮（v1.1 提级）

**现象**
`main/index.js:16` 使用 `titleBarStyle: 'hiddenInset'`，既没有 `frame:false` 也没有 `titleBarOverlay`，preload 也没有任何窗口控制 IPC；界面在 `App.vue:228-230` 自绘了三颗圆点，但它们只是 div，无点击行为。

**证据**
- `main/index.js:9-23`（无 `titleBarOverlay`）、`preload/index.js`（无 window 控制 API）；
- 发布包截图 `发布包/images/01-主界面.png`：画面最顶端直接是应用 header + 三颗圆点，**没有原生标题栏，也没有最小化/最大化/关闭按钮**。

**影响**
用户只能 Alt+F4 或任务栏关闭；无法最小化/最大化/拖动窗口。这是主流程可用性问题，不是装饰问题——上一版定为 P2 是错的。

**修复方案（二选一，其中"实现 IPC 控制"为默认选择）**
- **A. 恢复原生标题栏**：删除 `titleBarStyle`，同时删除三颗圆点；
- **B. 保留自绘 header**：`titleBarOverlay` + Window Controls Overlay，或在 preload 暴露 `minimize/maximize/close/toggleMaximize` 并让圆点绑定；同时给 header 加 `-webkit-app-region: drag`，按钮区域 `no-drag`。

**验收**：最小化、最大化/还原、关闭、拖动标题栏移动、双击最大化全部可用；`Alt+Space` 系统菜单正常。

### FE-25 串口订阅寄生在 DataMonitor 上（v1.1 新增）

**现象**
唯一的 `serial:data` 订阅点是 `DataMonitor.vue:386`，App 的 `@data="onData"`（`App.vue:303`）只是二次上抛。波形、PID 智能体、录制、Rx 计数全部依赖 DataMonitor 处于挂载状态。

**影响**
- 任何"把 DataMonitor 改成 v-if / 按需加载"的优化（包括 FE-02、FE-10 的后续演进）都会让波形与录制静默停摆，且不报错；
- FE-01 的批处理只能落在 DataMonitor 里，架构上继续耦合。

**修复方案**
抽出 `useSerialStream()`（或直接在 App `onMounted` 订阅），App 成为唯一消费方：

    batch → rxCount / pushSerialContext / recording
          → chartRef.appendBatch(batch)
          → pidAgent.pushSerialBatch(batch)
          → DataMonitor 只负责展示（消息、表格）

DataMonitor 改为接收 messages 或通过事件接收 batch，不再自己订阅 IPC。

**验收**：临时用 v-if 去掉 DataMonitor，波形与录制仍工作；DataMonitor 卸载后 `listenerCount` 归零。

## 2. P1 详情

### FE-09 只写不读的响应式状态（v1.1 更正：8 个）

`App.vue:86-90,174-177`：`serialContext.connected / path / baudRate / protocol / latestValues / recentLines / lastProtocol / lastAnomaly` 共 **8 个字段无任何读取方**（grep 确认；`recentLines` 只被自身裁剪逻辑引用）。
注意：**`channelHistory` 是被消费的**（`WorkspaceAnalysis.vue:41,44,91`），不要误删。
**方案**：删除未使用字段；开销最大的是 `recentLines`（每帧一个对象 + 两次字符串），`latestValues` 只是 8 个数字。

### FE-10 消息/表格无虚拟化

`DataMonitor.vue:20-21`：5000 / 1000 上限，v-if 切子页时整段重建。
**方案**：窗口化渲染（可视区 ±1 屏 + spacer），或先降到 1000/300 并保留"导出全部"。

### FE-11 分析面板重复全量计算

`WorkspaceAnalysis.vue:38` 每次依赖变化遍历最多 9600 样本；`:90` 的 `samples` 每次新建最多 1200 对象，而模板只取 `.length`（`:222`）。
**方案**：统计节流到 1Hz；`samples` 只算长度，完整样本在点"生成响应分析"时才算。

### FE-12 打字机 + 深监听（v1.1 补充）

`PidAgentPanel.vue:196-224`：`deep:true` 被 `shownLen` 每 16ms 触发；速度 +2 字符/帧（125 字/秒）。
**方案**：用 `watch(() => messages.value.length)` 替代 deep（因为 `callLlm` 非流式，文本一次性到达，安全）；但工具行 running→done 变化不再触发滚底，滚动改用 `ResizeObserver` 或对"最后一条消息状态"做 rAF 节流监听；速度提到 6~10 字符/帧；`prefers-reduced-motion` 时直接全显。

### FE-13 ECharts 重绘与 shift

`WorkspaceChart.vue:241-247` 每 33ms 重建完整 option；`:233-235` 超 2000 点后每样本 8 次 `shift()`。
**方案**：环形缓冲；结构不变时只 `setOption({ series })`。

### FE-14 图标全量注册（v1.1 更正：293 个）

`main.js:3,37-38`：`import * as ElementPlusIconsVue` 后逐个 `app.component`。实测该包导出 **293** 个组件（非"上千"）。
已核对全部模板：图标均为 import 绑定（`SerialPanel.vue:192`、`WorkspaceAnalysis.vue:226-229` 的 `:icon="X"`、`WorkspaceChart.vue:389`），无字符串解析式用法，删除全局注册不会白屏。
**方案**：删除注册循环，用 `rollup-plugin-visualizer` 对比产物体积。

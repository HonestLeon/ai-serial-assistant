## 一、总体结论

本次提交完成了**调参策略工具化的第一版原型**：在原有五个基础工具之外，新增两个策略入口，将已有的本地确定性调参策略封装为 Agent 可以调用的工具。

第一版的方向合理，安全机制没有被绕过，但目前更适合作为**仿真单环试验功能**，尚不适合默认启用或直接用于真实串口自动调参。

建议当前验收结论为：

> **仿真单环策略原型有条件通过；真实串口策略、默认启用和效率提升结论暂不通过。**

# 二、上次改动总结

## 2.1 新增的工具

在原有五个基础工具之外，新增两个策略工具：

| 工具 | 作用 |
| --- | --- |
| `list_pid_strategies` | 返回当前可用策略、适用范围和执行边界 |
| `run_pid_strategy` | 执行一次指定的确定性调参策略，包括读取采集证据、调整参数和重新验证 |

原五个基础工具保持不变：

- `get_channel_stats`
- `get_channel_data`
- `set_pid_params`
- `set_feedforward_params`
- `set_target`

因此启用策略工具后，Agent 每次可看到七个工具；关闭后恢复为原来的五个工具。

## 2.2 封装的策略

第一版封装了两个策略：

| 策略 | 原有算法来源 | 职责 | 适用范围 |
| --- | --- | --- | --- |
| `staged_pid` | `pidSafety.buildFallbackSuggestion` | 复用 P→PI→PID 分阶段思路，执行一次确定性调整并复测 | 标准单环 `kp/ki/kd` |
| `recover_pid` | 同一算法，增加“候选增益不得增加”的限制 | 面对超调或振荡时进行一次保守降参并复测 | 标准单环 `kp/ki/kd` |

第一版明确不支持：

- 串级位置—速度 PID；
- 自定义 PID 参数键；
- 二分搜索策略；
- 前馈整定策略。

这样处理的好处是避免策略在没有充分证据时自行套用到不适用对象。

## 2.3 调用机制

整体机制可以概括为：

> **模型选择策略，策略工具读取真实采集证据，复用基础工具执行一次调整和验证。**

具体流程如下：

1. 模型先调用 `set_target` 触发一次阶跃采集。
2. 工具记录本次采集时的：
   - PID 参数；
   - 前馈参数；
   - 目标值；
   - 数据时间窗口；
   - 仿真截断和安全检测结果。
3. 模型调用 `run_pid_strategy` 选择策略。
4. 策略工具检查：
   - 是否有采集数据；
   - 参数、目标或前馈是否已经改变；
   - 是否为支持的单环配置；
   - 采集窗口是否完整；
   - 阶跃指标是否有效；
   - 是否已经达标；
   - 会话是否已经停止。
5. 策略工具调用本地 `buildFallbackSuggestion` 生成一次候选参数。
6. 参数修改继续调用 `set_pid_params`，因此仍经过：
   - 用户配置范围；
   - 系统上限；
   - 单步增幅限制。
7. 修改后再次调用 `set_target` 复测：
   - 仿真模式立即运行仿真并返回调整前后指标；
   - 串口模式下发指令后返回等待状态，等待真实数据窗口。
8. 采集完成后继续经过原有安全检测和回退机制。

## 2.4 返回状态

策略工具使用状态明确表达本轮结果：

| 状态 | 含义 |
| --- | --- |
| `evaluated` | 仿真模式下已完成一次调整和验证，不代表一定改善或达标 |
| `pending_validation` | 串口模式已下发调整，等待真实数据验证 |
| `waiting` | 串口采集窗口尚未完成 |
| `needs_data` | 没有数据、窗口失效或指标无效，需要重新采集 |
| `stale_data` | 采集后参数、目标或前馈发生过变化 |
| `accepted` | 当前窗口已达标，无需继续调整 |
| `not_applicable` | 当前状态不适用所选策略 |
| `unsupported` | 当前不是第一版支持的标准单环配置 |
| `safety_stop` | 采集触发安全机制或仿真发生截断 |
| `stopped` | 用户已经停止会话 |
| `validation_failed` | 参数已经修改，但复测过程失败 |

# 三、新策略存在的问题

## 3.1 阻塞问题一：串口复测可能没有新阶跃

策略修改参数后，会再次执行：

```text
set_target(observation.target)
```

即向设备重复发送相同目标，例如：

```text
SET_POINT 10
PID 1 0.3 0
SET_POINT 10
```

如果设备已经到达目标 10，第二次设置相同目标通常不会产生新的目标跳变，统计数据中的阶跃幅值可能为 0，无法验证新参数效果。

当前测试复现结果为：

```text
首次策略：pending_validation
窗口完成后再调用：needs_data
原因：缺少有限、有效的阶跃指标
```

### 改进方向

第一版应采取以下方案之一：

1. **最稳妥：策略工具暂时只允许在仿真模式使用；**
2. 实机改参后使用专门的双点阶跃或目标切换协议；
3. 增加“改参后重新收敛测量”工具，不依赖再次修改目标；
4. 明确要求固件把重复 `SET_POINT` 实现为重新启动斜坡，并形成正式协议。

在协议明确前，不应根据 `pending_validation` 宣称实机参数已经得到验证。

## 3.2 阻塞问题二：同一模型回合可以连续修改多次参数

系统提示词中要求：

> 禁止策略与基础工具在同一轮连续盲调。

但目前该要求只存在于提示词中，没有代码层面的每回合调整预算。

Agent Loop 会串行执行同一模型回复中的多个工具调用；每完成一次策略，又会生成新的采集证据，因此下一条策略调用可以继续修改参数。

实际复现中，模型在同一回合返回三个策略调用，结果为：

```text
模型回合数：2
参数写入次数：3
```

这可能：

- 绕过“前五轮观察期”的实际调参轮次；
- 让多个参数调整连续发生而没有模型重新观察；
- 与“每次执行一次调整与验证”的用户理解不一致。

### 改进方向

- 在 observation 中记录创建时的 turn 或调参轮次；
- 同一回合只允许一次参数调整；
- 第二次调用返回 `adjustment_budget_exhausted`；
- 增加“单回合多个 tool call”的单元测试。

## 3.3 重要问题：安全回退后被误判为旧数据

当第一次 `set_target` 采集完成后触发安全回退时：

- observation 保存的是回退前的参数快照；
- 当前参数已经被安全机制修改；
- 下一次策略调用先比较快照，返回 `stale_data`；
- 因此无法返回更准确的 `safety_stop`。

### 改进方向

- 优先判断 observation 中记录的安全状态；
- 或在安全回退后同步更新 observation 的参数快照；
- 增加“采集阶段已经触发安全回退”的测试。

## 3.4 重要问题：策略结果不会计入上下文压缩

当前压缩逻辑只统计 `get_channel_*` 工具返回的数据。

但 `run_pid_strategy` 会返回完整的 `before`、`after`、`applied`、`capture` 和 `finalPid`，其中 `before/after` 体积较大，却不会计入 50KB 压缩阈值。

实测一次策略结果约为普通统计结果的数倍。随着策略调用增加，上下文可能持续膨胀而不触发压缩。

### 改进方向

- 将策略结果标记为数据型结果，纳入压缩统计；
- 或让策略只返回精简摘要，完整数据仍通过 `get_channel_stats` 获取；
- 增加“策略结果计入压缩”的测试。

## 3.5 默认启用早于效果验证

当前策略工具默认开启，而文档同时说明：

> 真实模型新旧对照和真实硬件验证尚未完成。

这意味着新功能在没有完成效果对照前，已经成为默认流程。

### 改进方向

- 正式发布前默认关闭；
- 真实串口模式强制关闭；
- 完成同条件、多次的新旧 A/B 对照后，再决定是否默认启用。

## 3.6 测试入口与覆盖范围需要补强

目前策略测试独立于 `test:analysis`，只运行原回归命令时不会执行新测试。

同时仍缺少以下测试：

- 串口重复相同目标；
- 采集后已经发生安全回退；
- 同一回合多次策略调用；
- 建议参数与当前参数完全相同；
- 缓冲窗口起点被淘汰；
- 策略结果的上下文压缩计量；
- `list_pid_strategies` 返回契约；
- 系统提示词中的策略规则。

### 改进方向

增加统一测试入口，例如：

```json
"test": "npm run test:analysis && npm run test:strategies"
```

并补齐上述边界测试。

## 3.7 提交可读性与仓库卫生问题

本次提交普通 diff 显示大幅增删，但忽略行尾后实际改动很小，说明多个文件被整体转换了换行符。

影响包括：

- diff 难以审查；
- `git blame` 失效；
- 后续容易产生无意义冲突；
- `git diff --check` 出现大量行尾空白提示。

提交信息 `0927` 也不利于后续检索。

### 改进方向

- 统一仓库换行符；
- 增加 `.gitattributes`；
- 后续使用可检索的规范提交信息。

# 四、建议的改进优先级

## P0：进入实机或默认启用前必须处理

1. 解决串口同目标复测没有新阶跃的问题；
2. 增加同一回合最多一次参数调整的机制；
3. 修复安全回退后被误判为 `stale_data` 的问题。

## P1：完成在线对照前应处理

1. 将策略结果纳入上下文压缩统计；
2. 策略开关默认关闭，真实串口强制关闭；
3. 增加统一测试入口和关键边界测试。

## P2：工程维护

1. 统一换行符并增加 `.gitattributes`；
2. 后续提交使用规范的提交信息；
3. 在完成在线 A/B 对照前，不宣称策略工具已经提升效率或成功率。

# 五、验收建议

当前可以验收为：

> **策略工具第一版仿真原型完成：已具备两个单环确定性策略、统一工具入口、原有安全机制复用、开关对照、单元测试和电机仿真冒烟。**

完成 P0 问题并补充测试后，再进行真实模型 A/B 对照和真实硬件验证。

# PID Agent 策略工具（第一版）

## 设计与范围

依据《PID调参Agent策略工具化设想》实现。模型选择策略，确定性工具执行一个调整周期，原有参数护栏和采集后安全机制继续生效。面板“启用确定性策略工具”可关闭，保留五个基础工具作为对照组。

策略清单由 `list_pid_strategies` 返回，`run_pid_strategy` 接受 `strategy`：

| 策略 | 原有算法 | 职责 |
| --- | --- | --- |
| staged_pid | pidSafety.buildFallbackSuggestion | 单环 P→PI→PID 的一次确定性调整与复测 |
| recover_pid | 同一算法，限制候选增益不增加 | 超调/振荡下的一次保守降参及复测 |

只支持明确的 kp/ki/kd 单环配置。串级的内环需要独立速度响应指标，第一版拒绝自动套用位置响应；模型继续用原有基础工具。二分法需要同工作点、同前馈、同参数条件的上下界证据，本版暂未开放，避免让模型凭空提供边界。前馈策略尚未纳入。

## 执行契约

1. 先用 set_target 采集。策略从工具内部记录的参数快照与数据窗口取得指标，模型不能传入指标或伪造验证结果。
2. 参数、前馈、目标变化后旧窗口失效；窗口未满返回 waiting，缓冲淘汰或指标无效则要求重新采集。
3. 一次调用最多一次参数修改，复用 set_pid_params 的限幅和增幅限制，再用 set_target 复测。
4. 仿真返回 evaluated 与 before/after、proposed/applied、护栏说明、finalPid；安全触发返回 safety_stop，包含原有回退结果。
5. 串口仅返回 pending_validation，等待完整数据窗口再作判断。下发指令不等于设备确认或效果达标。
6. 用户停止后不再启动下一动作。验证异常返回 validation_failed，明确参数已改变，交回基础采集流程。
7. 不额外调用模型，不保证候选参数改善；异常恢复也不是稳定性证明。真实硬件仍须独立保护和操作规程。

## 验证

`npm run test:analysis`：原有回归测试。

`npm run test:strategies`：策略确定性、非法输入、无数据、旧数据、范围裁剪、串口等待、停止、串级拒绝、保守恢复、安全回退、Agent 工具路由与关闭开关。

## 在线对照方案（待执行）

使用同一模型/API、相同初始 PID、目标、仿真参数、噪声条件及验收阈值。分别开启/关闭策略工具，各运行至少五次；记录模型轮次、外部工具调用次数、内部参数调整次数、总耗时、最终误差/超调/稳定时间、达标率、安全触发次数和异常次数。串级作为不适用策略的回归对照。先仿真，之后独立进行真实硬件验证。

单独报告每次结果和跨次分布，不能用“一次策略调用”掩盖内部调整与采集成本；失败和未达标试验也必须保留。仅当效果不劣化、无新增安全问题且轮次/耗时有一致改善时，才能声称策略工具提升效率。没有运行在线 API 对照，不能把 stub LLM 集成测试写为真实模型效果验证。
